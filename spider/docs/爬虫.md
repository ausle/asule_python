## HTTP协议

计算机通信时，通信双方约定好的一个规则。 常见的协议有：TCP/IP协议，HTTP协议。
浏览器和服务器之间的数据交互，遵守的协议就是HTTP协议。

请求：
- 请求行：请求方法（GET/POST）、请求链接、协议
- 请求头：
- 请求体：

响应：
- 状态行：协议、状态码
- 响应头：
- 响应体：服务端返回的内容







| 请求头 | 含义 |
|---|---|
| `Host` | 请求访问的域名；HTTP/1.1 中通常需要。 |
| `User-Agent` | 客户端软件和设备信息。 |
| `Accept` | 客户端希望接收的响应内容类型，例如 HTML 或 JSON。 |
| `Accept-Language` | 客户端偏好的语言，例如 `zh-CN`。 |
| `Accept-Encoding` | 客户端支持的响应压缩方式，例如 gzip 或 br。 |
| `Authorization` | 认证信息，例如 Bearer Token 或 Basic 凭证。 |
| `Cookie` | 携带此前由服务器设置的 Cookie，常用于会话登录状态。 |
| `Referer` | 表示请求通常从哪个页面跳转而来。 |
| `Origin` | 表示请求来自哪个源（协议、域名和端口），常用于跨域判断。 |
| `Content-Type` | 说明请求正文的数据格式，例如 JSON 或表单。 |
| `Content-Length` | 请求正文的字节长度。 |
| `Cache-Control` | 对缓存的使用提出要求，例如 `no-cache`。 |
| `Pragma` | 较旧的缓存控制方式，常见于兼容用途。 |
| `Connection` | 控制连接行为，例如 HTTP/1.1 中的 `keep-alive`。 |
| `Range` | 请求资源的一部分，例如下载文件的某个字节区间。 |
| `If-Modified-Since` | 询问资源自某时间后是否有更新。 |
| `If-None-Match` | 根据 ETag 判断资源是否变化，常用于缓存校验。 |
| `If-Match` | 只有资源匹配指定 ETag 时才执行操作。 |
| `If-Range` | 配合 `Range` 使用；资源没变化时返回部分内容，否则返回完整内容。 |
| `Origin` | 指明页面来源；注意它和 `Referer` 的用途不同。 |
| `DNT` | 曾用于表达“不跟踪”偏好，实际是否遵守取决于服务端。 |
| `Upgrade-Insecure-Requests` | 表示客户端偏好使用 HTTPS 等安全连接。 |
| `Sec-Fetch-Site` | 描述请求与发起页面之间的站点关系，如同站或跨站。 |
| `Sec-Fetch-Mode` | 描述请求模式，例如导航、`cors` 或 `no-cors`。 |
| `Sec-Fetch-Dest` | 描述请求内容的用途，例如文档、图片或脚本。 |
| `Sec-Fetch-User` | 表示请求是否由用户操作触发，常见值为 `?1`。 |
| `X-Requested-With` | 一些旧式网页会用它标记 AJAX 请求，常见值是 `XMLHttpRequest`；不是所有请求都有。 |
| `X-Forwarded-For` | 代理服务器可能用它传递客户端 IP；不能盲信客户端自行提供的值。 |
| `X-Forwarded-Proto` | 代理服务器可能用它说明原始请求使用 HTTP 还是 HTTPS。 |
| `X-Request-ID` | 一些服务用它标记请求，便于日志追踪。 |
